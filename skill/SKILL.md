# Paiban — 中文长文档 → WPS 原生可编辑 .pptx

一条命令把课程稿、内训稿、汇报稿变成能在 WPS 里双击打开、直接改字加页、保存后版式不崩的
`.pptx`。产出的每一页都是真实母版占位符，没有图片兜底；中文字体别名、标点挤压、避头尾、
首行缩进 2 字符、行距 1.5 都落在 OOXML 属性上。

## 何时用这个 Skill

- 用户手上有一份中文长文档，想变成要现场讲或要分发的演示文稿。
- 用户抱怨「生成出来的 pptx 在 WPS 里字体是方块 / 标点把行撑开 / 行距缩进要逐页重排」。
- 用户要复核一份已有 `.pptx` 的中文版式是否达标。

不适用：要图片、数据图表、旁白音频、转场动画（不做）；输入是 PDF / 图片 / 视频（不做）；
要可视化编辑模板或导入外部模板（不做，v0.1 只内置两个模板族）。

## 安装

```bash
pip install paiban                                   # 发布到 PyPI 后
git clone https://github.com/SuperMarioYL/paiban     # 或从源码
cd paiban && pip install -e .
```

装好后 `paiban` 就是命令名；发布到 PyPI 后 `uvx paiban ...` 与 `paiban ...` 等价（uvx 按需拉
一个隔离环境）。

## 命令

### 1. build：长文档 → deck

```bash
paiban build 课程稿.md -o 课件.pptx --template courseware
```

- 输入：`.md` / `.markdown` / `.txt` / `.docx`。省略 `-o` 时输出与输入同名、换 `.pptx` 后缀。
- `--template` 只接受 `report`（汇报）或 `courseware`（课件），缺省 `report`。
- 默认调 DeepSeek 做语义分段（页序 / 标题 / 要点 / 备注）。设置 `DEEPSEEK_API_KEY` 即启用：
  `export DEEPSEEK_API_KEY=...`。**没有 key 不报错**，改用文档结构规则切分，只损失语义分段质量。
- 60 秒内出页，无服务端、无数据库，全部本地跑。

### 2. verify：版式 lint

```bash
paiban verify 课件.pptx
```

复核 `.pptx` 里的 OOXML 属性：字体别名是否解析、标点挤压是否应用、首行缩进与行距是否达标、
避头尾是否开启、有没有残留图片兜底。判定基准是内置中文版式规范（首行缩进 2 字符、行距 1.5、
避头尾开启、无图片兜底）；给别的工具（例如 ppt-master）生成的 pptx 跑一次，差异会直接显示出来。

### 3. fix：给已有 deck 补版式

```bash
paiban fix 外来稿.pptx
```

对已有 `.pptx` 跑同一套中文版式 pass，就地改写属性。适合拿别人的模板出的稿子做二次交付。

## Agent 工作流

1. 确认输入文件路径与用户要的模板族（课件用 `courseware`，汇报用 `report`）。
2. 跑 `paiban build <稿子> -o <输出.pptx> --template <模板族>`。
3. 看输出里的**页序来源**：
   - `deepseek`：语义分段由模型给出，页序更贴原文语义。
   - `rules`：降级了。把降级原因（没有 key / 调用失败）如实告诉用户，别把规则切分说成模型分段。
4. 跑 `paiban verify <输出.pptx>`，把 lint 报告里 `warn` 的项读出来；全 `ok` 再交付。
5. 交付时提醒用户两件事：文件要在 **WPS** 里打开编辑；`verify` 只复核了 OOXML 属性，
   渲染结果需要按下面的「WPS 往返验收清单」人工确认一次。

示例触发：`/paiban 把这份课程稿做成课件`。

## 输出契约

| 位置 | 内容 | 来自 |
| --- | --- | --- |
| 封面 | 文档标题 | 第一个一级标题；docx 的 core title；`.txt` 首行；都没有则文件名 |
| 内容页 | 标题 = 章节标题 | 文档里的标题结构 |
| 内容页 | 要点 = 该章节的列表项；没有列表项时用正文段落 | 文档结构，不编造 |
| 内容页 | 备注 = 该章节的正文段落（讲稿） | 文档结构 |
| 章节页 | 只有标题、没有要点 | 空标题行（例如「第一部分」下面直接是「1.1」） |

- 一页最多 6 条要点，超出的部分自动出「（续）」页，不丢内容。
- 要点页用正文版式，空要点页用章节版式——章节版式不保证有正文占位符，要点会被静默丢掉。
- 生成物里**不应有图片**：`verify` 会检查这一条。

## 中文版式规则

| 规则 | 落到 OOXML 的哪里 |
| --- | --- |
| 字体别名回退 | 别名表（微软雅黑 / 宋体 / 黑体 / 楷体 / 仿宋 / 等线 / 思源黑体 / 思源宋体 + 拉丁族）解析后写 `<a:latin>` `<a:ea>` `<a:cs>` 三字体槽；别名表外的字体保留拉丁槽、只补东亚槽 |
| 标点挤压 | 连续全角标点（任一侧也是全角标点）按半宽挤压，把 run 拆段后写 `<a:rPr spc>` 负字距 |
| 避头尾 | `<a:pPr eaLnBrk="1">` + `<a:pPr hangingPunct="1">`，行首行尾半宽交给渲染器，不改文本内容 |
| 段落版式 | 首行缩进 2 字符（按段落字号换算成 `<a:pPr indent>`）、行距 1.5（`<a:lnSpc><a:spcPct>`）、段前后间距、两端对齐 |

版式是确定性代码：同一份输入两次运行逐属性一致。模型只决定页序，不写任何 OOXML 属性。

## 读 verify 报告

| check | 看什么 | 出现 warn 说明 |
| --- | --- | --- |
| `font_alias` | 中文 run 的东亚字体槽 | 有中文 run 没有东亚字体槽，或槽里的字体不在别名表——中文可能落到不可用字体上 |
| `punct_compress` | 含连续全角标点的段落 | 该挤压的段落没有负字距 |
| `paragraph_layout` | 首行缩进 / 行距 / 对齐 | 缩进不是 2 字符、行距不是 1.5、或对齐与模板不符 |
| `kinsoku` | `eaLnBrk` | 段落没有显式打开东亚换行与禁则 |
| `real_shapes` | 占位符与图片 | 有页面没有占位符，或生成物里出现了图片 |

## 诚实边界：WPS 部分没有被自动验证

`verify` 只复核 `.pptx` 里的 OOXML 属性，**不渲染、不驱动 WPS 进程、也不断言任何 WPS 版本的
排版结果**。下面三件事必须人工在 WPS 里确认：

1. 本机是否装了别名表里的字体，以及 WPS 实际选中了哪个字体来渲染中文。
2. 标点挤压与避头尾在 WPS 里的渲染结果（行首行尾半宽、禁则处理是否生效）。
3. 在 WPS 里改字 / 复制页 / 保存之后版式是否保持。

目标版本区间：**WPS Office 2019 及以上（含 WPS 365）**——这是 v0.1 声明支持的范围，不是实测结论。

### WPS 往返验收清单

| 步骤 | 动作 | 期望 |
| --- | --- | --- |
| 打开 | 双击 `.pptx` 用 WPS 打开 | 中文字体不回退、没有方块 |
| 改字 | 在任意一页改一段文字 | 首行缩进 2 字符与行距 1.5 仍在 |
| 加页 | 复制一页或新建一页 | 新版式跟着母版走，缩进行距一致 |
| 保存 | 保存后重新打开 | 属性没被 WPS 改写回默认值 |
| 复核 | 对保存后的文件重跑 `paiban verify` | 告警与保存前一致 |

## 模板族

v0.1 只内置 `report`（汇报）与 `courseware`（课件）两个模板族，不支持导入外部模板。模板族
JSON 里同时带母版版式映射和版式参数（字体、字号、缩进、行距、段前后、对齐），schema 见
`src/paiban/deck.py` 里 `load_template()` 的 docstring。

## 排错

| 现象 | 原因 / 处理 |
| --- | --- |
| 输出说 `rules`，页序是按段落切的 | 没有 `DEEPSEEK_API_KEY`，或 DeepSeek 调用失败；按输出里的原因处理，或接受规则切分 |
| `不支持的输入格式` | 输入是 PDF / 图片 / 视频等 v0.1 不吃的格式，先转成 markdown / txt / docx |
| `没有内置模板族` | `--template` 只接受 `report` / `courseware` |
| 封面标题是文件名 | 文档里没有一级标题（`.txt` 也没有可识别的编号标题行），加一行标题即可 |
| `verify` 报 `font_alias` warn | 稿子里有别名表外的字体；把该字体补进别名表，或改稿子里的字体名 |
